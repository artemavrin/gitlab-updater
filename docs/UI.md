# gitlab-updater — UI

React + Ink для интерактивной поверхности. Ниже — что это значит архитектурно и как выглядит каждый экран.

---

## 1. Ink и требование «ноль зависимостей на сервере»

Противоречия нет, если разделить сборку и запуск:

- **В исходниках** — `react` + `ink` (и только они; примитивы select/input/spinner пишем свои, ~120 строк на все, чтобы не тянуть цепочку мелких пакетов на закрытый контур).
- **На сервере** — один файл. `npm run build` → esbuild → `dist/gitlab-upgrade.mjs`. Никакого `node_modules`, `npm install` через прокси и разъезда версий.

Деплой: `scp dist/gitlab-upgrade.mjs server:` → `sudo node gitlab-upgrade.mjs plan`.
`dist/` коммитим только на тегах релиза — чтобы не шуметь диффом в обычных PR, но чтобы на изолированной машине хватило `git clone` без сборки.

---

## 2. Ядро не знает про UI

Это главное следствие Ink. Оркестратор не печатает — он **испускает события**:

```js
bus.emit({ t: 'step:start',   step: 3, version: '16.11.10-ee' })
bus.emit({ t: 'phase:ok',     phase: 'backup', size: 2.1e9, ms: 192000, path: '...' })
bus.emit({ t: 'migrations',   remaining: 47, closedLast10m: 8 })
bus.emit({ t: 'interrupt',    safe: false, why: 'идёт dpkg' })
```

```
Core ──► EventBus ──┬──► JSONL-журнал на диске   (источник правды)
                    └──► Renderer
                           ├─ Ink        TTY
                           ├─ Plain      нет TTY, --plain, вывод в файл
                           └─ JSON       --json, для мониторинга
```

Три следствия:

1. **`> log.txt` даёт нормальный лог**, а не мусор из перерисовок. Fullscreen-TUI в редиректе — классическая беда Ink-приложений; здесь её нет по построению.
2. **`attach` почти бесплатен.** Журнал на диске — источник правды, значит отдельный процесс может его читать и рисовать тот же экран. `run --detach` уходит под `systemd-run`, `gitlab-upgrade attach` подключается. **Обрыв SSH больше не убивает шестичасовой апгрейд** — это не косметика, а главная причина испорченных апгрейдов по SSH.
3. **UI тестируется** — `ink-testing-library` рендерит в строку, снапшотим экраны на записанных потоках событий.

## 3. Правила оформления

| | |
|---|---|
| Ширина | работает от 80 колонок, использует до 120 |
| Цвет | 4 роли: `ok` зелёный, `warn` жёлтый, `critical` красный, `dim` серый; `accent` голубой — только текущий элемент |
| `NO_COLOR`, `--no-color` | уважаем |
| Рамки | нет. Разделитель — пустая строка. Отступ слева 1 пробел |
| Спиннер | максимум один на экран — тот, что действительно работает сейчас |
| Язык | русский, колонки выровнены моноширинно |

Смысл ограничений: экран обновляется каждую секунду часами подряд. Всё, что мигает и перерисовывается без нужды, за шесть часов превращается в раздражитель.

```
   10 пройдено · 2 предупреждения · 0 критических

   1  16.3.9-ee      обязательная остановка   бэкап полный     ~90 мин
   2  16.7.10-ee     обязательная остановка   бэкап быстрый    ~40 мин
   3  16.11.10-ee    обязательная остановка   бэкап быстрый    ~50 мин
   4  17.3.7-ee      обязательная остановка   бэкап быстрый    ~35 мин
   5  17.5.5-ee      обязательная остановка   бэкап быстрый    ~30 мин
   6  17.11.6-ee     цель                     бэкап быстрый    ~45 мин

   Итого ~5 ч · оценка, реальное время зависит от размера БД
   Предзагрузка пакетов: 6 × ~1.1 ГБ = 6.6 ГБ

 Отката нет. Downgrade невозможен — миграции БД необратимы.
 Единственный откат — бэкап или снапшот VM, сделанный до старта.

 Дальше
   sudo gitlab-upgrade run --yes --detach --backup-hook /root/snapshot.sh   ← рекомендую
   sudo gitlab-upgrade run --yes
```

Заметки по решениям:
- **Причина ограничения пути показывается явно.** Если путь обрезан, вместо строки «цель» будет `17.11.6-ee   потолок Ubuntu 20.04` — пользователь сразу понимает, почему не 18.x.
- **Рекомендуемая команда — первой**, с `--backup-hook`. Инструмент подталкивает к снапшоту, потому что это единственный настоящий откат.
- Абзац про отсутствие отката — на экране, а не в README.

## 5. `run` — основной экран

```
 GitLab Upgrade · 15.11.13-ee → 17.11.6-ee              шаг 3 из 6 · 01:47:12

 ●───────●───────◐───────○───────○───────○
 16.3.9  16.7.10 16.11.10 17.3.7  17.5.5  17.11.6
 41 мин  38 мин  сейчас

 Шаг 3 · 16.11.10-ee                                                 00:41:09
   ✓ место на диске            139 ГБ свободно
   ✓ бэкап быстрый             2.1 ГБ · 3 мин · /mnt/backup/gitlab/20260830-1412
   ✓ установка пакета          из кэша · 6 мин
   ✓ сервисы                   12/12 running
   ⠋ фоновые миграции          осталось 47 · −8 за 10 мин · осталось ~59 мин

 Журнал                                                        [l] свернуть
   14:53:02  BackfillCiPipelineVariables            готово
   14:53:41  осталось 48
   14:54:12  BackfillProjectStatistics              23%
   14:54:51  осталось 47

 Ctrl-C сейчас безопасен: миграции идут внутри GitLab и продолжатся без нас.
 [l] журнал   [d] отсоединиться   [Ctrl-C] прекратить наблюдение
```

### 5.1 Индикатор безопасности прерывания — ключевая деталь

Строка внизу меняется по фазе, потому что цена Ctrl-C разная:

```
 Ctrl-C сейчас безопасен: миграции идут внутри GitLab и продолжатся без нас.
```
```
 Ctrl-C сейчас опасен: идёт dpkg. Прерывание оставит пакет в битом состоянии.
 [d] отсоединиться — процесс продолжит работу
```

И Ctrl-C в опасной фазе **не убивает процесс молча**, а спрашивает:

```
 ⛔ Сейчас идёт установка пакета (dpkg).
    Прерывание может оставить систему в состоянии, из которого
    придётся выходить руками через dpkg --configure -a.

    [d] отсоединиться, апгрейд продолжится      ← почти наверняка то, что нужно
    [Ctrl-C ещё раз] всё равно прервать
    [любая клавиша] вернуться
```

Такое умеет только TUI — и это главный аргумент за Ink в этом инструменте: не красота, а то, что пользователь в три часа ночи не убивает `dpkg` по привычке.

### 5.2 Прогресс миграций — измеренный, не угаданный

`осталось 47 · −8 за 10 мин · ~59 мин` — экстраполяция по фактическому темпу, а не по числу проектов. Темп упал до нуля на 30+ минут → строка становится жёлтой: `темп 0 за 30 мин — возможно, миграция застряла`. Появилась failed → красный и немедленная остановка.

## 7. `proxy test`

```
 Проверка прокси

   ✓ конфигурация       socks5h://10.0.0.5:1080
                        источник: /etc/gitlab-upgrade/config.json
   ✓ TCP                10.0.0.5:1080 · 12 мс
   ✓ SOCKS5 handshake   auth: username/password
   ✓ CONNECT            packages.gitlab.com:443
   ✓ TLS                cert OK · DigiCert · до 2027-01-14
   ✓ HTTP GET           /gitlab/gitlab-ee/... → 200
   ✓ apt через прокси   apt-cache madison gitlab-ee → 47 версий
   ✓ apt напрямую       archive.ubuntu.com доступен без прокси

   Всё в порядке.
```

При падении — конкретная причина и следующий шаг:

```
   ✗ TLS                self-signed certificate in certificate chain

     Похоже, прокси перехватывает TLS. Добавьте его корневой сертификат:
       sudo gitlab-upgrade config set proxy-ca /путь/к/corp-root.crt

     Проверку сертификата инструмент не отключает. Это не мешает работе:
     целостность пакетов гарантирует GPG-подпись репозитория, а не TLS.
```

## 8. Без TTY — `--plain`

Автоматически при редиректе, в systemd, в cron. Никаких ANSI и перерисовок, grep-friendly:

```
2026-08-30 14:12:03 [ok]    проверки: 10 пройдено, 2 предупреждения, 0 критических
2026-08-30 14:12:03 [info]  план: 6 шагов, 15.11.13-ee -> 17.11.6-ee
2026-08-30 14:12:04 [info]  шаг 1/6 16.3.9-ee: начало
2026-08-30 14:12:04 [info]  бэкап полный: начало
2026-08-30 15:31:47 [ok]    бэкап полный: 187 ГБ за 79 мин
2026-08-30 15:38:31 [ok]    установка 16.3.9-ee: из кэша за 6 мин
2026-08-30 15:41:02 [info]  миграции: осталось 132
2026-08-30 16:19:55 [ok]    шаг 1/6 16.3.9-ee: готово за 2:07:51
```

`--json` — тот же поток событий по одному JSON-объекту в строке, для внешнего мониторинга.

## 9. Структура UI-кода

```
src/ui/
  render.jsx            выбор рендерера: Ink | Plain | JSON
  useEventStream.js     подписка на EventBus либо tail JSONL (для attach)
  screens/
    Plan.jsx  Run.jsx  Setup.jsx  ProxyTest.jsx  Doctor.jsx
  components/
    CheckList.jsx       строки ✓ ! ✗ с выравниванием
    PathChain.jsx       ●───◐───○ с подписями
    PhaseList.jsx       фазы шага
    LogPane.jsx         хвост журнала, сворачиваемый
    SafetyBar.jsx       индикатор безопасности Ctrl-C
    Select.jsx  Input.jsx  Spinner.jsx    свои, без внешних пакетов
  theme.js              4 цветовые роли + NO_COLOR
src/render/
  plain.js  json.js     не-TTY рендереры на том же потоке событий
```

Экраны — чистые функции от потока событий. Значит снапшот-тест: подать записанный JSONL реального апгрейда → сравнить кадры. Никакого GitLab и терминала для этого не нужно.
