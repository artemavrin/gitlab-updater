# Репетиция на живом GitLab

Офлайн-тесты проверяют, что код правильно ведёт себя на записанных ответах.
Они не проверяют ничего из того, что случается на живой машине: как на самом
деле выглядит вывод `gitlab-backup`, сколько идут миграции, что делает
`apt-get install` при занятой блокировке dpkg.

Стенд — Ubuntu 22.04 без systemd, GitLab Omnibus ставится **из apt**, как на
сервере. Официальный образ `gitlab/gitlab-ee` не годится: там апгрейд делается
сменой образа, а не apt, и инструмент такой инстанс справедливо отвергает.

## Требования

- Docker, ~8 ГБ RAM, ~25 ГБ свободного диска.
- **Прямой доступ к `packages.gitlab.com`** или прокси, который не портит
  многогигабайтные загрузки (см. «Известное ограничение» ниже).
- Если выход в сеть через прокси — задайте `PROXY` и положите CA рядом:
  `cp /path/to/ca.crt rehearsal/ca-bundle.crt`.

## Запуск

```sh
cd rehearsal
docker build --build-arg PROXY="$HTTPS_PROXY" -t gitlab-rehearsal:base .
sh rehearse.sh 17.11.4-ee.0 17.11.7-ee.0     # откуда и куда
```

`rehearse.sh` ставит исходную версию, поднимает runit, ждёт готовности
инстанса, а затем прогоняет по нему настоящий инструмент: `check` → `plan` →
`doctor` → `run --yes` → повторный `check`. Всё, что инструмент напечатал,
остаётся в `rehearsal/out/`.

## Что репетиция проверяет, а офлайн-тесты — нет

| | |
|---|---|
| `gitlab-backup` | реальный вывод, реальный размер, реальное время |
| `gitlab-ctl status` | настоящий формат на живом инстансе |
| фоновые миграции | настоящий счётчик и настоящая скорость |
| `apt-get install pkg=version` | реальное поведение dpkg и postinst |
| resume | прерывание на настоящей фазе, а не на подделанной |

## Проверка контейнера

Инструмент считает контейнер критической находкой (`omnibus-container`) и
отказывается работать — Docker и Helm живут по другим правилам. Для стенда
проверка снимается переменной окружения:

```sh
GITLAB_UPGRADE_ALLOW_CONTAINER=1 node gitlab-upgrade.mjs run --yes
```

Это намеренно **не флаг CLI**: переменная не попадает ни в справку, ни в
каталог `api`, и снятая проверка не превращается в «ок» — она остаётся
предупреждением в выводе. Иначе репетиционная поблажка однажды уехала бы
в продакшен молча.

## Известное ограничение стенда

В окружении, где эта репетиция писалась, живая установка не завершилась.
Через egress-прокси стенда GET на пакет (~1.5 ГБ) отдавал тело **длиннее
заявленного `Content-Length`**: HEAD сообщал 1 559 811 266 байт, GET
приносил 1 561 902 042, и так воспроизводимо для разных версий. apt
справедливо отвергал пакет по контрольной сумме.

Это не проблема GitLab и не проблема инструмента — и обходить её отключением
проверки подписи нельзя. Репетицию нужно гонять там, где загрузка
многогигабайтного файла доходит целой.
